## Findings

1. **M2-001 — P1: Compiler silently discards requested semantics.**
   - File and line: `services/api/app/nl_compiler.py:186` and `:214`.
   - Reproduction: Compile “When a car enters Service Bay A with its hood open, create an alert”; save, approve, process. Also compile email, Python-execution, and “car or truck” requests.
   - Expected behavior: Preserve supported conditions; reject unsupported/ambiguous instructions.
   - Actual behavior: All compile without warnings/errors into car-only notifications. The hood condition disappears and an actual notification executes with zero visual verification.
   - Minimal suggested fix: Reject unconsumed clauses and multiple classes; explicitly preserve supported visual conditions and restrict accepted actions.

2. **M2-002 — P1: Zero or missing confidence confirms an action.**
   - File and line: `services/api/app/teacher.py:80`, `:310`; dispatch gate `services/api/app/pipeline.py:307`.
   - Reproduction: Provider returns `{"label":"yes","confidence":0.0}` or `{"label":"yes"}` for an approved visual workflow.
   - Expected behavior: Missing positive confidence fails validation; insufficient confidence remains non-confirming, consistent with PRD event correctness.
   - Actual behavior: Both persist `visual_status=ok` and execute a notification.
   - Minimal suggested fix: Require positive-response confidence and enforce an explicit minimum confidence before confirmation; preserve unknown separately.

3. **M2-003 — P1: Overall timeout does not bound queue/retry duration.**
   - File and line: `services/api/app/teacher.py:206`, `:215`, `:258`.
   - Reproduction: Set overall/read timeout to 0.05 seconds and one retry; simulate two 50 ms read timeouts. Separately hold the semaphore during classify.
   - Expected behavior: One deadline covers queue acquisition, attempts and backoff.
   - Actual behavior: Retry duration was 0.601 seconds; semaphore acquisition remained blocked after 0.15 seconds. No overall deadline check exists.
   - Minimal suggested fix: Bound semaphore acquisition and enforce remaining monotonic time across transport and backoff.

4. **M2-004 — P1: Attempt budgets and actual-call counters are incorrect.**
   - File and line: `services/api/app/vlm_router.py:247`, `:273`; retry loop `services/api/app/teacher.py:216`.
   - Reproduction: Budget 1, one retry, HTTP 503 then valid output; separately route through UnavailableTeacher.
   - Expected behavior: Each outbound attempt consumes budget and increments actual request counters; unavailable providers make zero counted requests.
   - Actual behavior: Two HTTP attempts consume one reservation and report one call. UnavailableTeacher reports one call with no outbound request.
   - Minimal suggested fix: Enforce/account for each transport attempt, including retries; separate invocation, attempt, result and unavailable counters.

5. **M2-005 — P1: Router admission state breaks cooldown and in-flight sharing.**
   - File and line: `services/api/app/pipeline.py:284`; `services/api/app/vlm_router.py:220`, `:229`, `:239`.
   - Reproduction: Two consecutive visits under sampling 0/cooldown 3600 produce two confirmed notifications. Concurrent identical inputs under sampling 2/cooldown 5 return a confirmed owner and `suppressed_sampling` duplicate.
   - Expected behavior: Cooldown spans candidates in a stable documented scope; concurrent identical requests share the in-flight result without a new reservation.
   - Actual behavior: Unique event keys make pipeline cooldown ineffective; admission gates reject duplicates before the in-flight lookup. Deduped counter remains zero.
   - Minimal suggested fix: Use stable cooldown identity and attach in-flight waiters before new-request admission. Bound completed-result/expired-scope retention while correcting this state lifecycle.
