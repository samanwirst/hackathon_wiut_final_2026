## Findings

1. **M1-010 — P1: Action executes after successful disable**
   - File and line: `services/api/app/pipeline.py:348`.
   - Reproduction: Gate `_dispatch_action` after the event commit; disable through the API, confirm `enabled=false`, then release dispatch.
   - Expected behavior: Completed revocation suppresses queued actions.
   - Actual behavior: A notification is created and the event becomes `done` after disable returns successfully.
   - Minimal suggested fix: Serialize disable and dispatch admission, recheck authoritative enabled state inside that boundary, and record cancellation explicitly.

2. **M1-011 — P1: Crash recovery duplicates external webhook delivery**
   - File and line: `services/api/app/actions.py:228`; recovery at `services/api/app/pipeline.py:249`.
   - Reproduction: Mock receiver returns HTTP 200; simulate a crash before the action commit; recover and reprocess.
   - Expected behavior: Recovery does not blindly repeat a possibly completed external action.
   - Actual behavior: Receiver observes event IDs `[1, 1]`; database contains one successful execution. The first uncommitted attempt is lost.
   - Minimal suggested fix: Persist dispatch intent before delivery; reconcile interrupted attempts or require receiver-enforced stable idempotency keys.

3. **M1-012 — P1: DNS guard does not protect the delivery connection**
   - File and line: `services/api/app/actions.py:186`; preflight at line 105.
   - Reproduction: Allowlist a hostname; return a public IP during authorization and loopback during HTTPX's subsequent lookup. Use an intercepted socket under direct egress.
   - Expected behavior: Only validated addresses can receive the webhook.
   - Actual behavior: HTTPX attempts `127.0.0.1:9876` after a successful public-address check. No real connection was made by the reproduction.
   - Minimal suggested fix: Pin transport connections to validated addresses while preserving hostname/TLS validation, or enforce equivalent controlled egress restrictions.

4. **M1-013 — P1: Truncated video is silently reported complete**
   - File and line: `services/api/app/pipeline.py:299`; successful completion at line 359.
   - Reproduction: Generate a 60-frame MP4, remux with `ffmpeg -c copy -movflags +faststart`, truncate to 65%, upload, enable, and process.
   - Expected behavior: Reject the incomplete input or expose failed/partial processing.
   - Actual behavior: HTTP 201 upload; decoder reports a partial file; source reports `processed`, `error=null`, and seven analyzed samples instead of ten.
   - Minimal suggested fix: Detect premature decoder termination using decoded progress and reliable metadata, with appropriate tolerance, and expose the failure.

5. **M1-014 — P2: CI omits dependencies needed by its unit tests**
   - File and line: `.github/workflows/ci.yml:46`.
   - Reproduction: Restrict collection to the job's declared dependency set and run `tests/unit`.
   - Expected behavior: All selected tests collect and execute.
   - Actual behavior: Collection fails because `test_webhook_auth.py` imports undeclared `httpx`; `SQLAlchemy` is also required through `app.db`.
   - Minimal suggested fix: Install `httpx` and `SQLAlchemy` in that job or move these tests to a backend dependency job.
